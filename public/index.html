Jonah Frame

An always-on web app for a repurposed 1280 × 800 touchscreen photo frame. The primary screen shows what is happening now and what comes next for a child who cannot yet read. The schedule engine derives that sequence from recurring activities and date-specific overrides. It distinguishes exact times, approximate times, and untimed events, so an activity with no start time can appear without creating a false countdown. Wake and bedtime cues follow the routine even when the illustrated sky changes with the actual sunset.

The waterfront scene combines a fixed backdrop with independently animated objects. A fresh vessel position can drive the painted ferry. When the feed goes stale or the vessel docks, the ferry eases from its last rendered position into decorative motion. An earlier implementation hid it during those gaps, causing it to blink in and out as the feed refreshed. The night reflection was also moved off the background and attached to the ferry so both follow the same animation.

The frame updates the clock every second and rebuilds other regions only when their inputs change. That keeps touch targets in place on the older Android WebView. The calculator and letter board use temporary local state and clear on dismissal. A separate parent interface writes routine and photo changes. The Cloudflare Worker enforces read-only access for the frame and checks photo visibility again when an image is requested, so hiding a photo also revokes access through its direct URL.

Crateflip

An archived prototype that explored two ways for producers to share music. The first iteration modeled beat discovery on digging through records, with artist pages, searchable track metadata, and audio previews. A Next.js frontend and an Express API shared schemas for their data contracts.

In that version, uploads began with a private draft record and a short-lived signed URL. The browser sent the audio directly to object storage. The API checked ownership and confirmed that the file existed before the record could become public. A stable playback route issued fresh signed URLs, keeping a shared track address usable after an individual storage URL expired.

The later iteration focused on a shareable artist page with links and a single featured track. PostgreSQL enforced one active track per profile. When a track was replaced, the prior record was written to history in the same database transaction as the profile update. Audio lived in separate storage, so a failed database update required a separate cleanup step for newly uploaded files. The prototype is offline.
